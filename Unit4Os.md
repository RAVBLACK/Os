# UNIT IV: Operating Systems - Exam Notes

## 1. Deadlock
A **deadlock** is a situation where two or more processes wait forever for resources held by one another.

**Example:** P1 holds the printer and waits for the scanner. P2 holds the scanner and waits for the printer. Both wait forever.

## 2. Necessary Conditions for Deadlock
Deadlock occurs only when all four conditions exist together:

1. **Mutual Exclusion:** A resource can be used by only one process at a time. *Example:* Only one process can use a printer.
2. **Hold and Wait:** A process holds one resource while waiting for another. *Example:* P1 holds a printer and waits for a scanner.
3. **No Preemption:** A resource cannot be forcibly taken; it must be released voluntarily. *Example:* The OS cannot take the printer away while a process is printing.
4. **Circular Wait:** Processes form a circular chain, each waiting for a resource held by the next. *Example:* P1 waits for P2, and P2 waits for P1.

## 3. Deadlock Prevention
**Deadlock prevention** designs the system so at least one necessary condition cannot occur.

- **Remove Mutual Exclusion:** Make resources sharable where possible. This is not possible for every resource, such as a printer.
- **Remove Hold and Wait:** Require a process to request all resources at once, or release held resources before requesting new ones.
- **Remove No Preemption:** If a process requests an unavailable resource, take back its held resources and retry later.
- **Remove Circular Wait:** Assign a fixed order to resources and require processes to request them in that order.

**Example:** Require every process to request the scanner before the printer. This prevents circular waiting.

## 4. Deadlock Avoidance
**Deadlock avoidance** checks whether allocating a resource will keep the system in a **safe state**. A safe state means there is an order in which all processes can finish.

### Banker’s Algorithm
The Banker’s Algorithm grants a request only if the system remains safe.

**Formula:** `Need = Max − Allocation`

**Steps:**
1. Calculate the Need of every process.
2. Set `Work = Available`.
3. Find a process whose `Need <= Work`.
4. Assume it finishes and add its allocated resources: `Work = Work + Allocation`.
5. Repeat until all processes finish.
6. If all processes can finish, the state is safe. Otherwise, it is unsafe.

## 5. Deadlock Detection
**Deadlock detection** allows deadlocks to occur and checks the system to find them.

- For a single instance of each resource, a cycle in the resource-allocation graph indicates deadlock.
- For multiple resource instances, use a detection algorithm based on Available, Allocation, and Request.
- Processes that cannot finish during the detection algorithm may be deadlocked.

**Example:** P1 waits for a resource held by P2, and P2 waits for a resource held by P1.

## 6. Deadlock Recovery
**Deadlock recovery** removes a deadlock after it has been detected.

1. **Process Termination:** Abort one or more processes to break the deadlock. The OS may terminate all deadlocked processes or one at a time.
2. **Resource Preemption:** Take a resource from one process and give it to another.
3. **Rollback:** Return a process to an earlier safe state and restart it.

**Victim selection** should consider priority, resources held, work completed, and recovery cost. The same process should not repeatedly be selected, or it may suffer starvation.

# Memory Management

## 7. Memory Management
**Memory management** is the OS function that manages RAM. It allocates memory to processes, tracks its use, and frees memory when processes finish.

## 8. Logical and Physical Address
- **Logical address:** Address generated by the CPU; also called a virtual address.
- **Physical address:** Actual location in RAM.
- **MMU:** The Memory Management Unit translates logical addresses into physical addresses.

**Example:** If the base address is 1000 and the logical address is 200, the physical address is `1000 + 200 = 1200`.

## 9. Swapping
**Swapping** moves a process temporarily from RAM to secondary storage and brings it back when needed.

**Steps:** The OS selects a process, stores it on disk, uses the freed RAM for another process, and brings the swapped process back when required.

## 10. Contiguous Memory Allocation
In **contiguous allocation**, each process is given one continuous block of memory.

- **First Fit:** Select the first free block large enough.
- **Best Fit:** Select the smallest free block that is large enough.
- **Worst Fit:** Select the largest available free block.

**Steps:** Check free blocks, choose a suitable block using the selected method, allocate it, and update the remaining free space.

## 11. Fragmentation
- **Internal fragmentation:** Wasted memory inside an allocated block.
- **External fragmentation:** Free memory exists, but it is split into small scattered blocks.
- **Compaction:** Moves processes so scattered free space becomes one large block.

## 12. Paging
**Paging** divides logical memory into fixed-size **pages** and physical memory into equal-size **frames**. A page table maps pages to frames.

**Advantages:** Avoids external fragmentation and allows a process to occupy non-contiguous frames.  
**Disadvantage:** May cause internal fragmentation.

**Address calculation:** `Physical Address = Frame Number × Page Size + Offset`

**Steps:** Divide the logical address into page number and offset; use the page table to find the frame number; combine the frame number with the offset to get the physical address.

## 13. Segmentation
**Segmentation** divides a program into logical parts called segments, such as code, data, and stack. Each segment has a base address and a limit.

**Address calculation:** `Physical Address = Base + Offset`

The offset must be within the segment limit. Otherwise, an error occurs.

**Steps:** Find the segment number and offset, check the offset against the limit, and add the offset to the segment base.

## 14. Segmentation with Paging
This method divides a program into segments and then divides each segment into pages.

**Steps:**
1. The logical address identifies a segment, page, and offset.
2. The segment table locates that segment’s page table.
3. The page table gives the frame number.
4. The frame number and offset produce the physical address.

It combines the logical organization of segmentation with the memory-allocation benefits of paging.

# Virtual Memory

## 15. Virtual Memory
**Virtual memory** allows a program to run without loading the entire program into RAM. The OS keeps some parts in secondary storage and loads them when required.

**Advantages:** Runs programs larger than RAM and allows more processes to share memory.  
**Disadvantage:** Too much disk activity can slow the system.

## 16. Demand Paging
**Demand paging** loads a page into RAM only when the process actually needs it.

**Steps:** A process requests a page; if it is in RAM, execution continues. If absent, a page fault occurs, the OS loads it from disk, updates the page table, and resumes execution.

## 17. Page Fault
A **page fault** occurs when a process accesses a page that is not currently in RAM.

**Handling steps:**
1. The CPU traps to the OS.
2. The OS checks whether the memory access is valid.
3. It finds a free frame or selects a page to replace.
4. The required page is loaded from disk.
5. The page table is updated.
6. The interrupted instruction is restarted.

# Page Replacement Algorithms
Page replacement is needed when a page fault occurs and RAM has no free frame.

## 18. FIFO (First-In, First-Out)
FIFO replaces the page that entered memory first.

**Steps:** Maintain pages in arrival order; on a page fault, remove the oldest page and load the requested page.

**Example:** If pages entered in order are 2, 5, 7, FIFO replaces page 2 first.

## 19. LRU (Least Recently Used)
LRU replaces the page that has not been used for the longest time in the past.

**Steps:** Track the last use of each page; on a page fault, find the least recently used page and replace it with the requested page.

## 20. Optimal Page Replacement
Optimal replaces the page that will not be used for the longest time in the future.

**Steps:** On a page fault, check when each page currently in memory will be used next; replace the page whose next use is farthest away. If a page will never be used again, replace that page.

Optimal gives the minimum possible page faults, but future references are not known in real systems. It is mainly used for comparison.

### Comparison

| Algorithm | Page selected for replacement | Main point |
|---|---|---|
| FIFO | Oldest loaded page | Simple |
| LRU | Least recently used page | Uses past activity |
| Optimal | Page used farthest in future | Minimum possible faults |

## 21. Thrashing
**Thrashing** occurs when the system spends more time swapping pages between RAM and disk than executing processes.

**Causes:** Too many processes in memory, insufficient RAM, and high page-fault rate.

**Effects:** Low CPU utilization, slow system performance, and excessive disk activity.

**Prevention:** Reduce active processes, allocate more frames, increase RAM where possible, and use working-set or page-fault-frequency techniques.

**Example:** If a process repeatedly needs pages that are not in RAM, the OS keeps loading and replacing pages. The process makes very little progress.
